## 1. 档位与目标（照抄 `SPEC.md` §3 表 + §4.8，不重述）

| 项 | 目标（SPEC） |
|---|---|
| 流体 | **PBF/FLIP 1000 万粒 GPU 60 FPS〔目标〕**；512³ 网格 GPU 60 FPS〔目标〕 |
| 显存 | **1000 万粒 GPU ≤ 4 GB**（⇒ 每粒预算 ≈ 400 B） |

| 技术族 | GPU PBF（Müller 2013，poly6/spiky，密度约束迭代 3~4）；GPU FLIP/APIC（高精档，稀疏哈希网格 512³） |

## 2. 路线（`SPEC.md` §8 已定，本文只复述 + 补本机事实）

- **统一入口**：自有 trait `PhysGpuBackend`（骨架已在）；主实现 = **wgpu**（Vulkan/Metal/DX12/WebGPU）；
  着色器 = **rust-gpu → SPIR-V**；**NVIDIA 极致路径** = cuda-oxide SIMT + C ABI 主机桥
  （**唯一**允许的独立后端；"禁止单一厂商绑定"是骨架写死的硬性要求）。
- **本机事实（本轮实测）**：`RTX 4060 Ti 34 CU / 8 GB` + `Intel iGPU 64 CU / 7.8 GB`，
  OpenCL 3.0 运行时可枚举 ⇒ **两条路线本机都能验**（wgpu 走 D3D12/Vulkan，NVIDIA 路径也有硬件）。

## 4. 确定性口径（**crux**；三条可选，附推荐）

骨架已给出仓库自己的口径：**"必须 CPU 回退且结果一致（同档参数下位姿哈希一致，
容差 = 严格模式量化容差）"** ⇒ 即**量化哈希 + 容差**，不是逐位一致。三条路：

| 口径 | 做法 | 优 | 劣 |
|---|---|---|---|
| **A 决定性设计** | GPU 内核内**固定序累加**（每格/每邻域按索引序串行求和、**不用原子加**） | 可与 CPU **位级一致**（与我这轮 CPU 并行化同一原则） | 慢一些（放弃原子/乱序归约） |
| **B 量化哈希门**（骨架口径） | 位置/速度**量化后**比哈希，容差 = 严格模式量化容差 | 允许浮点顺序差 ⇒ GPU 可用最快写法 | 不是位级 ⇒ 需定义量化步长与容差表 |
| **C 报告档** | 像 wasm/arena 那样只报数、不入门 | 零约束 | 无回归保护 |

**推荐**：**A 优先、B 兜底**——能位级就位级（密度/力这类逐粒相位天然可以），做不到的相位
（跨粒归约，如 PBF 的密度约束全局迭代）用 B 并在档里**逐相位写明用的是 A 还是 B**。

## 5. CI 策略（决策点②）

CI runner **无 GPU** ⇒ 建议：① CI 照旧跑 CPU 档（不变）+ 编译/测试 GPU crate 的 **CPU 回退路径**
（保证不断链）；② GPU 实测走**本机门**（照 wasm/arena 先例：本地命令 + JSON 基线入库 + 记机器指纹
——本机 RTX 4060 Ti 可验）；③ 是否把"GPU 档不在 CI 内"写成正式口径，需拍板。

## 6. 首里程碑（M4 step 1，**最小可测**，不做 PBF/FLIP 全档）

**"GPU 版密度 + 力相位"**（与现有 WCSPH **同数学、同场景、同哈希口径**）。理由：
1. 与 CPU **天然对拍**——我这轮已有的仪器正好用：30 万粒规模探针（`sph_scale`）、相位计时
   （`phase_us`）、并行/串行逐位门（`parallel_equals_serial_bitwise`）；
2. 复用**同一份状态布局**（SoA `pos/vel/dens/press/pmass` + 计数排序网格）⇒ 苹果对苹果；
3. 它的读数**决定 PBF/FLIP 值不值得按 SPEC 全做**（若 GPU 在 30 万粒上给不出数量级优势，
   就该回头谈档位，而不是照抄规格）。

**判据（首里程碑）**：① 一致性——同场景 CPU/GPU **量化哈希一致**（或位级，按 §4 的 A/B）；
② 性能——GPU ms/tick 与对 CPU（8 线程 124 ms/300k）的**加速比**；③ 显存——按 §3 的
≤400 B/粒 预算核对实测占用；④ 不与单一厂商绑定（wgpu 路径在 Intel iGPU 上也要跑通）。

## 7. 前置与风险

- **rust-gpu 工具链**：nightly 依赖 + 构建脚本改动（CI 与本机都要）；可先考虑"**预编译 SPIR-V
  入库**"降低工具链耦合（待选型）；
- **wgpu 版本钉法**：本仓依赖纪律（棘轮 + 理由），需与 §3 的基线更新一并办；
- **显存预算**：10M 粒 ≤4 GB ⇒ 每粒 ≤400 B——PBF 需 `pos/vel/den/pres`（4×16 B = 64 B）+ 邻域
  索引 + 迭代 scratch ⇒ **要真算一遍**（首里程碑后给出实测表）；
- **与 CPU 档的界面**：`PhysGpuBackend` 已有 trait；耦合（刚体↔流体）在 GPU 档大概率仍是
  "GPU 流体 + CPU 刚体"（PBF/FLIP 的粒子↔刚体碰撞走同一套边界粒子口径）——待定。
