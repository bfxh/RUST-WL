## 1. CI 分层（用户令「学习其他仓库工作流，静态等都加上去」）

**抽取来源**：`bfxh/ark`（TS：19KB ci.yml + 分文件工作流 + 汇总门 + 最小权限 +
SHA 固定）、`bfxh/unified-rx-mcp`（单 core.yml）、`bfxh/arch-optimize`
（mypy/ruff/tests 分文件 + `continue-on-error` + 报告产物）。

**落地清单**（全部先在本地跑绿才入 CI，这是本轮唯一「零意外」的原因）：

| 层 | 内容 | 首跑结论 |
|---|---|---|
| 静态·文本 | typos（`_typos.toml` 只豁免确有语义的术语）/ actionlint / zizmor（在线）/ `discipline_scan.sh` / `vocab_scan.sh` | ✓ |
| 静态·依赖 | `cargo deny check`（deny.toml：公告/许可白名单/通配禁止/未知源）+ `cargo machete` | ✓ |
| 静态·代码 | `RUSTDOCFLAGS=-D warnings cargo doc` + 强化档 clippy（todo/unimplemented/dbg_macro/mem_forget/undocumented_unsafe_blocks/let_underscore_must_use） | ✓ |
| 报告 | `cargo llvm-cov`（`continue-on-error`，产物归档） | ✓ |
| 汇总门 | `gates-summary`：`needs` 全部 + `if: always()` + `contains(needs.*.result, failure/cancelled/skipped)` | ✓ |

**安全基线（zizmor 36 项 → 0 项）**：workflow 级 `permissions: contents: read`、
checkout 全 `persist-credentials: false`、第三方 action 按 commit SHA 固定
（唯一例外 `dtolnay/rust-toolchain@stable|nightly`，行内注明「ref 即工具链名」）。

**顺带修掉的真缺陷**（静态工具首次引入即命中）：2 处 rustdoc 断链
（`verts[face_start[i]..]`、`e ∈ [0,1]` 被当作链接语法）；workspace path 依赖缺
版本约束致 cargo-deny 解析失败（→ `{ version, path }` 双写，Cargo.lock 逐位不变）；
`xxhash-rust` 是 BSL-1.0（原白名单未列）；dependabot 缺 cooldown（→ 7 天）。

**首次真机 CI 的两个失败，都是「工具链认知错误」而非代码错误**：
① `install-action` 的合并写法 `tool: a,b,c` 失败（exit 76）→ 拆成逐个安装后
归因明确；② **actionlint 是 Go 工具，`taiki-e/install-action` 只覆盖 Rust 工具**
→ 改取 release 资产 + sha256 校验（`8aca8db9…`）。**这条经验写进纪律**：每个门
先在本地跑绿，CI 上的失败才能被归因到环境而不是逻辑。

**仓沪治理**：`dependabot.yml`（分组 + 限 2 并发 + cooldown）、
`pull_request_template.md`（自检清单 + **确定性影响栏**：强制回答哈希新旧全量
u128）、`ISSUE_TEMPLATE/{bug,task}.md` + `config.yml`。

**转公开与清理**：仓库由私有转 public（用户授权；私有仓 Free 计划 Actions 分钟
被账单拦截，全部 job 拒启）。转公开前先核了安全面（Mimosa 深度扫描 0 命中）。
`main` 上四个 GitHub 起步模板（`rust.yml`/`label.yml`/`stale.yml`/`summary.yml`）
经用户确认后删除——它们是占位模板、与 `ci.yml` 重复烧分钟、且含
`pull_request_target` 高权限触发器与未固定版本 action。

## 2. T3 窄相优化：三刀，全部量测驱动

**基线（8B 场景 `m1_scale 8 102400 100000`，160 tick）**：窄相每 tick 均值 14.34ms、
p95 41.03ms、**峰值 49.91ms**（验收 ≤25ms）。

**分相量测（第十八段）**：用临时仪表（`Instant` **纳秒**累加）在**串行路径**取
占比 —— fill 18.7% / sat 24.9% / clip 22.5% / poly_for 5.5% / 其余 ~28%。
**方法学教训（记档）**：① 并行路径每块 `clone` 仪表、汇总丢失；② `as_micros()`
对亚微秒值截断，会把绝大多数样本记成 0（我曾因此得出「填充为零」的假结论、
并被 8 线程下的禁用缓存实验「证实」——**两次都错**）。

| 刀 | 做法 | 收益 | 行为 |
|---|---|---|---|
| ① 盒对专用路径 | `(Box,Box)` 独立分支：体轴由 `(rot,half)` 直生并与预筛共用（`obb_separated` 返回轴）；免 `poly_for` 与 33 次旋转填充；`BOX_FACES` 面表按多面体面序/环绕序硬编码 ⇒ 特征号逐位不变 | 峰值 49.91→34.70ms（−30%） | **ULP 级变化**（顶点算术序不同），哈希更新并如实记录 |
| ② clip 去 normalize | 侧平面保留/穿越判定与插值参数均与尺度无关 ⇒ 省每 clip 4 次 sqrt+除法 | 含于① | — |
| ③ 退役分离预筛 | 预筛 15 轴是 SAT 21 轴子集（面轴差符号、分离度取 `|·|`）且只做拒绝 ⇒ 对真接触对是纯重复 | 峰值 34.70→31.56ms（−11%） | **哈希逐位不变**（实证：m0_gates/determinism 均不变） |
| ④ 流形输出预分配 | 块输出缓冲按上一帧产出数预留容量 | 峰值 31.56→30.56ms（−3%） | **哈希逐位不变** |

**钉板（4 块，全部做过敏感性验证——注入错误必须变红）**：
`box_sat_fast_matches_vertex_reference`（快/通用路径对拍，实测 Δ ≤7.2e-7 ⇒ 定量
界为 ULP 级）、`box_axis_order_and_orientation_is_pinned`（面序/棱序即契约）、
`box_dedicated_matches_generic_full_chain`（sep 位相等/特征号逐位相同/点差 ≤1e-5）、
`heightfield_crease_normal_is_not_blended`（折痕处不许出现面法线混合）。

**缺口归属（第十九段末）**：峰值 tick ≈234k 盒对/帧、8 线程 31.56ms ⇒ 每对墙钟
135ns、折算单核 1.08µs，而算术量级仅 0.1-0.2µs ⇒ **差距 5-10×，瓶颈在访存局部性
与分支**。并行加速比实测 6.3×（理想 8×），同样指向带宽。

## 3. T2 宽相尾：三连否定（含方法学价值）

**T2 尾基线（同场景 120 tick，每 tick 值）**：查询 均 7.47 / 峰 **22.64ms**；
树 均 2.74 / 峰 **12.17ms**（验收：宽相单 tick ≤15ms、树 ≤5ms）；AABB 均 0.95。
**读数陷阱记档**：同一行输出里 `broad` 是**累计值**而 `(AABB 树 查询)` 是**每
tick 值**——按累计差分会得到负的树耗时（我因此先误判「查询占峰 62%」）。

| # | 假设 | 做法 | 结果 | 处置 |
|---|---|---|---|---|
| ① | 查询峰 = 翻转帧全缓存失效的代价 | 唤醒只清自身缓存、入睡才全体失效（推理完备） | 查询 均 7.47→7.53、峰 22.64→**22.96ms**（无改善）；不变式测试与哈希均不变 ⇒ 行为等价但零收益 | **回退**（不引入该复杂度） |
| ② | 查询峰 = 候选数过多（fat 边距 0.5 上限） | 上限降到 0.15 | 树 +14%、查询 +8%、AABB +7%；窄相（对数量代理）不变 ⇒ 边距不是杠杆 | **回退** |
| ③ | 树峰 = 全量重建 | 用已有数据判定：n=202 400 ⇒ 阈值 `3·log2(n)+16=68.9`，实测 `tree_h` **恒 18** ⇒ **重建从未触发** | 诊断修正：树峰 = 每 tick 逐清醒体增量更新（`move_proxy_scaled` + 祖先链 refit ~18 层） | 文档修正 |
| ③b | 树峰 = 祖先链空走 | `fix_upwards` 提前退出（并集盒/高度未变即停） | 首轮两种形式均红（4/6 结构测试）→ **写最小复现后定位**：`fix_upwards` **同时被 `insert`/`remove` 调用**，二者会新建节点/改孩子集合，新节点首层即「自洽」⇒ 提前退出在首层误触发、祖先不再传播 | **已修并落地**：拆成 `fix_upwards`（全走，insert/remove 用）+ `fix_upwards_grow`（可提前退出，仅生长路径）；树峰 12.17→**7.34ms（−40%）**、均值 2.74→2.11ms、**哈希逐位不变**、12/12 测试绿 |

**树形无关性判定（同批数据即可，无需新跑轮）**：理想高度 `ceil(log2(n))`——
n = 202 400 ⇒ **18**；实测 `tree_h` 120 tick 恒为 **18** ⇒ **树高已达理论最优、
不存在链化退化**。故树峰剩余 2.34ms（7.34 → 验收 5ms）**不是树形问题**，而是
「每帧约 10 万次代理移动 × 提前退出后 1-3 层祖先 refit ＋ 约 40 万节点 × 48B
≈ 19MB 节点数组的指针追逐」这一**访存延迟**成本——与查询峰、T3 缺口的结论一致。

**改造方向的定量定夺（访存账，决定了该改什么结构）**：现状 = 二叉 AoS 节点
（盒 24B + 左右/父 12B + 高度/体 8B ≈ 48B），节点数 ≈ 40.5 万 ⇒ **19.4MB** 节点
数组；查询访存 ≈ 10 万查询 × 18 层 × 48B = **86MB/帧**——远超 L3 ⇒ **访存受限
坐实**（与前述所有量测一致）。三个候选的收益对比：

| 结构 | 节点数 | 遍历层数 | 查询访存/帧 | 降幅 |
|---|---|---|---|---|
| 现状（二叉 AoS） | ≈40.5 万 | 18 | 86MB | — |
| SoA 拆分（遍历只读盒+孩子 32B） | ≈40.5 万 | 18 | 58MB | −33% |
| **BVH4** | ≈202 399 | ≈9.0 | 43MB | **−50%** |
| **BVH8** | ≈101 199 | ≈6.0 | 29MB | **−67%** |

**结论：主杠杆是「宽节点」（每内部节点收纳 4/8 个孩子），不是单纯 SoA**——宽节点
同时压查询访存（层数 18→9 或 6）与 refit 链长（与刚落地的提前退出叠加）。代价是
插入/旋转逻辑更复杂、每层并集要更新 8 个子盒；但量测显示遍历主导，该代价划算。
**下一步设计：BVH8 优先（保留二叉版本作对照），落地前先用 `min_tree_*` 组把
不变量扩到宽节点形态（高度公式改 `1+max(子高)`、盒=8 子并集、父指针、包含性）。**

**收敛判断**：查询峰既非失效策略、亦非候选数，树峰亦非重建 ⇒ 与 T3 缺口归属
同一结论：**访存局部性/树形结构**。故 T2 尾 + T3 余项 ①③ + T4 小岛批应合并为
**一次「数据布局」投入**，不再各自试参数（本日四次实验已两次证明试参数无效）。

## 4. 内边去除：收口（有证据，非搁置）

1. 引擎 `Shape` 全枚举 = `Box/Sphere/Cylinder/HeightField`，**无三角网格**（全仓
   `Mesh|Triangle|Trimesh` 零命中）⇒ 经典「三角内边假接触」无处产生；
2. 高度场按**高度值采样**（非逐三角最近特征），结构上不属该族算法；
3. 剩余风险 = 折痕双线性混合 ⇒ 已钉板（50/50 混合仅 0.973 < 阈值 0.995 ⇒
   鉴别力成立，当前通过）。**触发条件**：引入三角网格/可变形地形时须重开。
