# 求解器极限与「彻底解决」路线（PLAN-solver-limits.md）

> **立此档的原因**：外部提出四条"终极方案"（XPBD / warm start · 迁 Bullet3/Jolt ·
> 分布式子空间多世界 · 定点数 + ECS），需要一个**集中对账 + 排期**的地方，避免反复重提。
> 逐条对账表在 `OPEN-PROBLEMS.md` P1「外部方案评估」段（含本会话实测依据）。

## 1. 「极限」在哪：一句话版本

- **残余侧已基本解决**：塔在 `16/1/64` 下 2400 tick 末态只剩 **3 体超阈**（阈值下 2497/2500）、
  且能**瞬时归零**（tick 2150 超阈 = 0）；pile5 **满睡 2000/2000**；默认档 Σv² **−29%**。
  成因也已定位并修掉（切向回拉对**滑动**接触的错误回拉，`DRIFT_STICK_RATIO` 粘着门，已落地）。
- **现在卡住的是「睡眠规则」**：本仓**岛级原子入睡**（整岛成员须**连续**低于阈值满 `sleep_time`），
  而少数体在阈值上**闪烁** ⇒ 大岛的睡眠窗口**永远被打断** ⇒ 岛上其余 ~1900 体陪睡。
- **性能侧**：P2/P3/P4 各差一截，且**第一件事是口径**（需 V2 §11 原文）。

⇒ 换句话说：**"塔不入睡"已经不是解算质量问题，而是"什么算睡着"的规则问题。**

## 2. 两条可执行的路（按性价比排序）

### 路 A：睡眠规则允许「岛内子块入睡」——**推荐先做**

- **现状**：`睡眠 = 整岛成员连续低于阈值满 sleep_time`。Rapier 允许**岛内子块**入睡
  （本仓 `awake` 已是**逐体**状态，改动面比想象小）。
- **实测依据**：`16/1/64` 塔 tick 2150 超阈 = 0 而仍未全睡；超阈数在 0–6 之间闪。
- **做法**：睡眠判定从"岛"下推到**连通子块**（或逐体 + 邻域一致性），
  保留唤醒的**传播**语义（唤醒仍沿接触图传递，避免"睡着被撞不醒"）。
- **代价/风险**：**行为改变** ⇒ 须过四哈希换代（ADR 0004 显式记新旧值）+ 金样三场景 +
  默认档四个冻结值 + arena 19/0/0 + 长跑稳定性门。
- **判据**：塔在 `16/1/64` 下 **2500/2500 入睡**，且 col45/pile5/m0_gates **不退化**；
  `m0_gates` 末态活跃不劣于现基线（4）。

### 路 B：把残余尾巴压到「舒适低于阈值」（标定，与路 A 不互斥）

- **现状**：`substeps=64` 已到只剩 3 体，但**闪烁**跨阈（偶尔归零、随即又冒出来）。
- **做法**：子步/迭代分配的档位标定。**注意**：`inner=1` 需要**足够子步**
  （`16/1/4` 曾发散、KE 44 万 J），高子步侧 2400 tick 未见发散。
- **判据**：角向超阈的**窗口均值持续为 0**（不是偶尔 0），且成本按**"入睡后活跃 tick"**口径复测
  （睡着的岛被跳过 ⇒ 稳态成本与"全程活跃"不是一回事）。

### 路 A 的实现规格（2026-09-21 读码后落定；**先读"陷阱"再动手**）

**现状代码**（`crates/vxl-phys-solver/src/lib.rs:922-972`）：三段逻辑绑在一起——
① 建岛把「与清醒体连通的睡眠体」收进来；② 循环里**任一成员 awake → 全岛置 awake**；
③ 只有**全员**低阈才累加计时器，`min_timer ≥ sleep_time` 才整岛入睡。

**⚠️ 陷阱（必须先知道）：A 的两半互相打架。**
我原计划写的是"睡眠判定下推到连通子块 + **保留唤醒传播**"，但读码后确认：
**"连通即唤醒"正是把睡眠钉成原子的那条规则**。静下来的主体块即使睡下去，只要它与
仍在颤的少数体**相连**，下一子步建岛就把它收进来 ⇒ "任一成员 awake → 全岛 awake" ⇒
**立刻被叫醒、计时器清零**。⇒ **只下推睡眠判定是无效的**。

**⇒ A 必须同时改两件事**：
1. **子块级睡眠判定**：在岛内取「自身低于阈值」的体构成的**接触子图**，按**连通分量**判断；
   分量全员计时器 ≥ `sleep_time` ⇒ 该分量入睡（该分量的体失活、速度清零）。
   （岛结构里已有 `island.manifs`，分量可在岛内局部算出 ⇒ 不必新建全局图。）
2. **唤醒从「连通即唤醒」改成「实质相互作用才唤醒」**：唤醒条件改为
   ① 与清醒体的**相对速度**超过 `sleep_linear/sleep_angular`；或 ② 该接触产生**有效法向冲量**
   超过阈值；或 ③ 外部唤醒（`set_awake`/新增体）。**只连通不唤醒**。

**⚠️ 效果未证（必须先算这笔账）**：A 未必能让塔全睡。塔残余那几体是**原地自转**
（|ω|≈0.1–0.2、|v| 多在阈值下），其**接触点表面速度 = ω×r ≈ 0.05 m/s**，
**正卡在阈值上** ⇒ "实质相互作用"判据可能照样判成"在动"、照样唤醒邻居。
并且：**Rapier 的塔是 |v|→0.000 真静止**（不需要子块睡眠）⇒ A 在语义上是
**给"没消灭干净的残余"打补丁**，B 才是去消灭残余。

**风险与门**：②动的是**安全保障**（现行规则同时兜着"睡着被撞不醒"）；须过
四哈希换代（ADR 0004）+ 金样三场景 + 默认档冻结值 + arena 19/0/0 + 长跑门；
**按仓内先例默认关**（`stabilization_iterations` / `detect_once_per_tick` 的路子），
先量它对塔到底有没有效果，再谈默认。

### ✅ 路 B 已成功（2026-09-21 实测，**塔第一次全体低于阈值**）

`16/1/128`、tower25、1200 tick（已落地粘着门下）：

| tick | 超阈（线/角/双） | 入睡 | KE |
|---|---|---|---|
| 650 | 0 / 1 / 0 | 1425 | 2.1 J |
| 700–950 | **0 / 0 / 0（连续保持）** | 1200–1425 | 2.5–3.9 J |
| 1000 | 0 / 0 / 0 | 1725 | 1.4 J |
| 1100 | 0 / 0 / 0 | 1925 | 0.7 J |
| 1200（末态） | **0 / 0 / 0** | **1875 / 2500** | **1.2 J** |

- 末态阈值分解：**仅线性 0 / 仅角速 0 / 双超 0 / 阈值下 2500（共 2500）**
- y 带完整 [0.25,12.25]、最深 0.006。
- 对照：修复前塔**任何**子步数都是 **0/2500 入睡、KE ~100 J** ⇒ 现在 **75% 入睡、KE ~1 J**。

⇒ **B 的机制判断被证实**：残余幅值压到"舒适低于阈值"后（连续 500+ tick 无超阈），
**岛级原子睡眠规则终于能触发**（`sleep_time` 只需 30 tick 连续低阈）。
⇒ **路 A（子块睡眠）很可能不再需要** —— 那条本来就是给"没消灭干净的残余"打补丁。

**代价与未验（诚实列出）**：
- ⚠️ **位置精度退化**：末态 `max|Δpos|` **0.1412 m**（基线 0.0794、sub64 为 0.0659–0.0777）
  ⇒ 高子步下塔的蠕变轨迹与参照体偏差更大，**这条要单独判定是否可接受**。
- ⚠️ **成本**：sub128 活跃期约 2× sub64（本机观测 ~1.2 s/tick），但**入睡后活跃 tick 归零**
  ⇒ 必须按"睡眠后的活跃 tick"口径复测稳态成本，不能拿活跃期数字当结论。
- ⚠️ **未过门**：`16/1/128` 的长跑稳定性、四哈希换代、金样三场景、arena、默认档冻结值。
- ⚠️ 末态仍有 **~625 体在睡/醒之间反复**（入睡数在 1875↔1925 波动）⇒ 还有更小的岛在循环，
  可再给 tick 或再上子步；**这属收尾标定，不是机制问题**。

### ❌ B 的收尾尝试之一：`sleep_timer` 保留假说——**否证（2026-09-21）**

**假说**：末态 0 体超阈却仍有 ~625 体不睡 ⇒ 是**牵连唤醒那句"一律清零"**把 `min_timer`
按回 0（塔蠕动 ⇒ 接触生灭 ⇒ 安静体反复被牵连进清醒岛）⇒ 全岛永远凑不满 `sleep_time`。
**实现**（已回退）：只对**在动**（超阈）的牵连体清零，安静的保留累计。

**读数（`16/1/128`，1200 tick，窗口均值 1000–1200 各 5 点）**：

| 变体 | 入睡数（窗口均值） | KE（窗口均值） | Δpos（末态） |
|---|---|---|---|
| 未精修 | **1865** | 0.96 J | 0.1412 |
| 保留计时 | **1860** | 0.84 J | 0.1465 |

⇒ **窗口均值完全相同（1865 vs 1860）⇒ 假说否证**，按"无实测净收益即回退"撤掉。
⇒ **方法论提醒（本条踩了两次）**：中途看单点时它"更差"（tick 900：725 vs 1200），
末态看又"更好"（1950 vs 1875）——**两个方向都不算数**，只有窗口均值给出"没差别"。
这类振荡量上**必须**用窗口均值，见 `OPEN-PROBLEMS.md` P1 的判据修正。
⇒ **下一步诊断（若要继续收尾）**：不是再猜语义，而是**先量**——岛内计时器为什么不涨。
可用现成计数 `sleep_resets`（`all_slow=false` 那条分支的计数）与"每岛 min_timer 的分布"
来分辨"有人快"还是"成员 churn"，再决定改哪里。

### ✅ 先量：诊断计数把阻塞点从"猜语义"变成两个数字（2026-09-21）

新增 `sleep_diag_take()`（只计数、**实测哈希不变** ⇒ 零行为影响，按仓内诊断先例可留）。
`16/1/128`、塔 900 tick：

```
有人快而拒 4,055,216 | 全慢但未满 2,359,636 | 入睡 87 | 等待中 min_timer 峰值 587 ms
```

**⚠️ 关键发现是"口径"，不是机制**：
- 引擎的睡眠阈值与金样**完全相同**（`sleep_linear = 0.04`、`sleep_angular = 0.05`，
  `vxl-phys-core/src/config.rs:189-190`）⇒ **不存在阈值口径差**（我先怀疑的是这个，核掉了）。
- 但：金样**每 50 tick 采样**、读到 **0 体超阈**；而引擎 **每个子步**判 `all_slow`，
  在 128 子步下被拒 **405 万次** ⇒ **残余在 tick 尺度"舒适低于阈值"，在子步尺度仍在反复跨阈**。
- ⇒ 这一条解释此前所有现象：为什么"末态 0 超阈却不睡"、为什么入睡卡在 ~1875 平台、
  为什么**加子步有效**（子步越小 ⇒ 子步内位移越小 ⇒ 跨阈越少）。
- ⇒ **与 Rapier 的对照（很可能是真正差别）**：它**每步判一次**睡眠（其 step = 我们的 tick），
  本仓**每子步判一次** ⇒ 子步越多、被判"有人在动"的机会越多 ⇒
  **同残余水平下它睡、我们不睡**。

### 下一个实验（有依据的假说，不是再猜语义）

**睡眠判据改为「每 tick 判一次」**：累积 `tick_dt`（与现行每 tick 的累计量等价），
使 tick 内的闪烁不再打断 `sleep_time` 窗口。
- 属性：**语义改变**（判据采样率）⇒ 按仓内先例**默认关**实现，先量塔。
- 风险：子步内剧烈振荡可能被"抽到安静瞬间"而误睡 ⇒ 必须在**低子步档**上验证不退化
  （这正是长跑门与金丝雀的活）。
- 若有效再谈默认（四哈希换代 + 金样 + arena + 长跑门）。

### ❌ 「睡眠判据改为每 tick 判一次」——**否证：发散**（2026-09-21）

**实现**（已回退）：只在**每 tick 的末子步**判 `all_slow`，计时器按**整 tick** 累积
（每 tick 累计量不变，故不是"更容易睡"，只是**采样更稀**）。

**读数**（`16/1/128`、塔 900 tick）：

| tick | KE | 超阈（线/角/双） | 入睡 |
|---|---|---|---|
| 350 | **11,632 J** | 12 / 2 / 25 | 0 |
| 500 | **113,155 J** | 2 / 0 / 28 | 2 |
| 550 | 29,987 J | 0 / 0 / 14 | 4 |

⇒ **发散**。把一个 tick 内的振荡"抽到安静瞬间"，就让体**在真的还在动的时候睡着** ⇒
冻结体与仍在动的邻居发生剧烈相互作用 ⇒ 注能爆炸。
⇒ ① 本档先前标注的风险（"抽到安静瞬间误睡"）**被证实为致命**；
② **这条同时揭示了「岛级原子入睡」存在的真正理由**：代码注释写的是"从机制上排除反复唤醒"，
   但实测显示更硬的理由是——**冻结体与运动体共存会产生非物理的剧烈相互作用**；
③ ⚠️ **对路 A 的直接警告**：A 让"安静的连通子块"先睡，同样造成冻结/运动共存
   ⇒ 必须保证该子块与运动体之间**没有显著相互作用**，否则会复现这次的发散。
⇒ **结论：只能去压残余（让它在**子步尺度**真的低），不能改判据的采样率。**

### ✅ B 续：便宜的档会**自己**收敛，只是慢（2026-09-21，sub128 × 2400 tick）

| tick | 入睡 | KE | \|v\|max | 超阈（线/角/双） |
|---|---|---|---|---|
| 1200 | 1875 | 1.2 J | 0.020 | 0 / 0 / 0 |
| 1800 | ~1950–2050 | ~0.5 J | 0.012 | 0 / 0 / 0 |
| 2200 | 2125 | 0.4 J | 0.011 | 0 / 1 / 0 |
| **2400** | **2225 / 2500（89%）** | **0.2 J** | **0.006** | **0 / 0 / 0** |

- 末态 `max|Δpos|` **0.1412**（与 1200 tick 的读数**完全相同** ⇒ 位置已基本定住）；
  y 带完整 [0.25,12.25]、最深 0.006。
- **入睡数一路在升**（1875 → ~2000 → 2125 → 2225），中间有 1950↔2225 的反复
  ⇒ **剩余 ~275 体是"硬核"**，但趋势是收敛而非平台。

  ⇒ "有人快"仍是主导项（子步尺度跨阈），与上面的诊断结论一致。
- ⇒ **不需要再上 sub256 就能继续收敛**（代价省一半）；剩余 ~275 体若要收净，
  可给更多 tick，或按路 A 处理（**须带"冻结/运动共存会发散"的警告**）。

### Δpos 的取舍曲线（2026-09-21，从已有日志汇总；**零新机器时间**）

塔25、落地修复后、同一 `16/1/<N>` 族：

| 档 | tick | 末态 `max\|Δpos\|` | 超阈（线/角/双） | 阈值下 |
|---|---|---|---|---|
| sub16（基线，**修复前**） | 600 | 0.0863 | 191 / 261 / 31 | 2017 |
| **sub32** | 1200 | **0.0669** | 0 / 22 / 0 | 2478 |
| sub64 | 1200 | 0.0777 | 0 / 8 / 0 | 2492 |
| **sub64** | 2400 | **0.0659** | 0 / 3 / 0 | 2497 |
| **sub128** | 1200 | **0.1412** | 0 / 0 / 0 | **2500** |
| sub128 | 2400 | **0.1412** | 0 / 0 / 0 | 2500 |

**两条从表里能直接读出的结论**：
1. **代价出现在 sub128 这一档，不是"越高越差"**：sub32 / sub64 的 Δpos（**0.0659–0.0777**）
   **优于**修复前基线 0.0863，只有 sub128 跳到 0.1412。
2. **它不是"睡着导致的漂移"**：sub128 在 1200 与 2400 tick 的 Δpos **逐位相同（0.1412）**，
   而这两点之间入睡数从 1875 涨到 2225（多了 350 个体冻结）。若冻结是原因，数值应当变化
   ⇒ **Δpos 的差别由轨迹在 tick ~1200 之前就定下了，与冻结无关**。

**⚠️ 一个必须先解决的口径问题（否则上表的"退化"可能不成立）**：
`max|Δpos|` 是**最大范数**——由**单个体**决定。本会话已经吃过一次同类教训
（`|v|max` 是离群指标：子步加到 32 时它反飙到 0.568，而超阈体数继续降 ⇒ 用它得出反结论）。
⇒ **0.1412 vs 0.0669 可能只是一个体的差别，而不是系统性保真退化**。
**在该口径解决之前，不应据此判定"sub128 退化"**。

**下一步（便宜的仪器改进）**：金样的 Δpos 打印改为**分布**（`mean / p95 / max`），
再看两档的差别是"整堆系统性偏移"还是"一个离群体"。这是 `over_threshold` 那次经验
（单点/极值 → 分布）的直接复用。

### 路 B 的当前落点（2026-09-21）

`16/1/128` 已到 **2500/2500 下阈（tick 采样）、~2225 入睡（89%）、KE 0.2 J**——**可用作保真档**
（但**先解决上一条的 Δpos 口径**再下这个结论）。
剩余 ~275 体不睡 = **闪烁者所在岛**；要继续收尾只剩两条：
① 给更多 tick 或再上子步（代价 ×2/档）；或 ② 路 A 的子块睡眠
（**带上"冻结/运动共存会发散"的警告**：必须排除该子块与运动体的显著相互作用）。

**B 已验证有效 ⇒ 按 B 继续收尾**（把最后的 churn 收掉 + 过门），**A 暂停**

**收尾的下一步只有两条**（"每 tick 判一次"那条实验已否证，见上）：① 再上子步；
② 路 A 子块睡眠（**必须带上"冻结/运动共存会发散"的警告**）。


## 3. 明确**不做**的（附理由，防重提）

| 方案 | 为什么不做 |
|---|---|
| 分布式子空间多世界 + 幽灵刚体 + 异步冲量传递 | **违反 ADR 0004 确定性承诺**（跨平台哈希门；"岛间无耦合"是**已证明**的事实）。竞态与时空不一致正是本仓用确定性换掉的东西 |

## 5. 纪律（沿用）
