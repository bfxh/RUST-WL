# ADR 0009：外部碰撞提供者通道（`Shape::Provider` + `ProviderColliders`）

- 状态：**accepted**（2026-09-14）
- 取代：无；被取代：无

## 背景（Context）

路线（`ROUTE.md`）的第一轴是**兼容**：任意域都要能与刚体碰撞。落地前的现实：
新增一种碰撞体（体素、trimesh、喷溅场）**必须改窄相 crate** 的 shape 分派
（`match shape` 加臂 + 专用算法），而窄相又不能依赖域 crate（DAG 反向依赖
⇒ 循环）。已有的先例是高度场：`Shape::HeightField(id)` + 由门面供给的
`hf_bounds[id]`（宽相 AABB）+ 窄相内的高度场专用路径——但那条路径是**内建**的，
不是插件式的。

## 决定（Decision）

1. **`Shape::Provider(id)`**（core）：外部碰撞提供者体的形状标识；静态 Marker
   语义（`mass_props` 按「不参与质量属性」处理、`bounding_sphere_radius` = ∞、
   CCD 最小半长 = ∞，均与高度场一致）。
2. **`interop::ProviderColliders`**（core）：窄相的唯一查询面——
   `bounds(id)`（宽相 AABB）+ `contacts_box(id, half, pos, rot, skin, out)`
   （盒形包络 → `InteropContact` 列表）。窄相**只依赖 core**，具体实现由门面/
   域 crate 提供（`vxl-phys::Providers` 持有体素体集合）。
3. **宽相**：`compute_pairs` / `shape_aabb` 增加 `provider_bounds: &[Aabb]`
   参数（与 `hf_bounds` 同机制），门面在注册时供给。
4. **只增不改（逐位不变）**：只有 `Shape::Provider` 体走新分支；既有形状
   （盒/球/圆柱/高度场）路径一字未动 ⇒ `m0_gates` / `determinism` 哈希逐位
   不变（已验）。
5. **首条端到端用例**（M2 贯通切片）：盒落在体素地面上——经完整管线
   （宽相 AABB ← provider bounds；窄相 ← `contacts_box_voxel`；解算；入睡）
   静置于体素顶面并入睡（门面测试 `box_falls_and_rests_on_voxel_provider`）。

## 后果（Consequences）

- 正面：新域接入 = `impl CollisionProvider` + 注册，**零改动窄相**；喷溅场/trimesh
  同路径可插；法线/深度/特征 ID 语义统一（`InteropContact`）。
- 已知限制（如实）：① 只有「盒 vs provider」有专用查询（球/圆柱/凸体走
  `CollisionProvider::contacts_box` 的默认角点采样可先兜底，专用解法待补）；
  ② provider-provider 对暂不支持（需要 provider 对偶解法）；
  ③ provider 数据变更（挖洞）后需调用方 `refresh_provider_bounds()` 刷新宽相 AABB
  （否则宽相用旧盒；窄相查询始终读实时数据）。
- 与高度场路径的关系：高度场仍是内建特化（列裁剪）——迁移到 provider 通道会改变
  行为（算法不同），属 M2 后续工作项（要求逐位不变 ⇒ 只能包一层不改数学）。
