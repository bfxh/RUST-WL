## 本段被否掉、但价值在"防复发"的四项

1. **扫掠内预积角向量**（`e7e3072`）：构建 −23%，**扫掠仅 −3%**；金样 col45
   45/45 入睡 → 40/45 ⇒ 回退。结论：**GS 扫掠是依赖链/延迟受限，不是算力受限**。
2. **关节热启动**（`0c12be0`）：链 −42%，但固定关节塔 **×19 且相邻块翻转**
   ⇒ 回退。结论：角行无姿态偏置时，旧姿态累积冲量会注入能量；要热启动必须先补
   姿态偏置 + 位姿突变门（接触通道靠特征匹配/距离门才成立）。
3. **裁剪内取模换分支**（`c2ba3ae`）：交错 A/B 2 低 1 高 ⇒ 噪声，回退。
4. **裁剪缓冲定长数组化（64 + 溢出）**（`2809723`）：先证逐位等价（43 套件 + 三哈希
   全绿不变），再交错 A/B 三轮**全部同向变慢**：窄相 **+26%**、p50 +6.5% ⇒ 回退。
   结论：**"删掉 push 开销"输给"缓存局部性 + 代码形状"**——给窄相结构体加 ~2 KB
   内联数组把热字段推远，`Index`/`IntoIterator` 的分支与 `Chain` 也比切片迭代难优化。

**四次的共同规律**：本引擎这一阶段的瓶颈是**访存局部性与依赖链**，不是指令数。
凡"看起来少算了什么"的改动，先按 RECIPES 的交错 A/B 量，再决定留不留。

## 方法学资产（本段新增，务必沿用）

- **交错 A/B 协议**：只读 worktree 检旧提交 + 独立 target 目录，两二进制交替跑
  （`git stash push -- 源码` 会被 Mimosa hook 拦；见 RECIPES）。
- **两道门**：时序（交错 A/B）+ 保真（金样 col45/pile5/tower25，`gold-sample/`
  是独立 workspace，命令要在该目录下跑）。**换代哈希的改动必须两道都过**。
- **探针分档**：相位级用 `probe::us`；亚微秒区段必须 `probe::ns`（`us` 会把单次
  亚微秒区间截断成 0——本段第一版裁剪读数因此差了 100×）。调用密度高（>1000 次/步）
  的区段用**整数计数器**，别用计时探针（自身开销 ≈25 ns/次）。
- **测量环境**：浏览器跑分对机器竞争敏感（同 hash：闲时 1.88 ms vs 全核 cargo 编译
  期间 3.14 ms）；跑分必须闲时做、同批内比较。

   换代哈希 + 金样两道门**。

   参数 + 同步 `vxl.ts`，建议单独一轮。
3. **关节热启动**：依赖第 2 项顺带补出的角行姿态偏置 + 位姿突变门。
4. 质量项融合（四处共享 `I⁻¹(r×dir)` 中间量）：预估 ≤5% 帧，换代哈希。
